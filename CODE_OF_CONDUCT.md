# Code of Conduct

## Our standard

KodeWork is intended to be a constructive technical community. Contributors, maintainers, users, and reviewers are expected to communicate respectfully, focus criticism on ideas and evidence, and make room for people with different backgrounds and experience levels.

Examples of welcome behavior include:

- giving specific, actionable technical feedback;
- acknowledging uncertainty and correcting mistakes;
- respecting privacy and security boundaries;
- helping newcomers understand project conventions without belittling them;
- disagreeing with an implementation while remaining respectful toward the person proposing it.

Unacceptable behavior includes harassment, discrimination, threats, sexualized conduct, stalking, doxxing, sustained personal attacks, deliberate intimidation, and publishing another person's private information or credentials without permission.

## Scope

This policy applies to repository Issues, Pull Requests, Discussions, review comments, project-maintained community spaces, and other public interactions made in an official project capacity.

Technical disagreement, rejection of a contribution, or a request for stronger evidence is not itself misconduct when expressed professionally and consistently with this policy.

## Maintainer responsibilities

Maintainers may edit or remove comments, close or lock threads, reject contributions, or restrict participation when behavior conflicts with this Code of Conduct. Enforcement should be proportionate, documented when practical, and focused on restoring a safe and productive project environment.

## Reporting conduct concerns

For sensitive conduct concerns, use a private contact method published on the repository owner's GitHub profile when available. Do not post private personal information, threats, or harassment evidence publicly merely to obtain maintainer attention.

If a situation involves an immediate platform-safety concern, impersonation, threats, or abuse that requires GitHub intervention, use GitHub's own abuse/reporting mechanisms in addition to contacting the project maintainer.

Security vulnerabilities are handled separately under [SECURITY.md](SECURITY.md).

## Enforcement approach

Depending on severity and history, maintainers may use one or more of the following responses:

1. clarification or a private/public warning;
2. removal of inappropriate content;
3. temporary restriction from project spaces;
4. permanent restriction for severe or repeated violations.

Retaliation against someone who raises a good-faith conduct concern is not acceptable.
