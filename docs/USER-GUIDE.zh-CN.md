# KodeWork 零基础使用指南

这份指南面向从未使用过 KodeWork、SSH、Tailscale、Herdr 或跳板机的人。请按顺序操作，不要把密码、Auth Key、私钥或真实服务器信息放进截图、Issue、日志或聊天记录。

> 安装包状态：当前可下载的桌面安装包是 **Windows 10/11 x64** 版本。可移植 Rust 核心会在 Windows、macOS、Linux 上检查，但原生 macOS/Linux 桌面安装包尚未发布。

## 0. 五分钟首次配置

如果你只想先跑通一台 Linux 主机，请严格按这条最短路径操作：

1. 在远程 Linux 上确认 SSH 可用：`ssh 用户名@主机地址`。
2. 在 KodeWork 首次启动页选择 **简体中文**；以后可在 **设置 / Settings → 语言 / Language** 切换。
3. 点击 **工作站 +**，只填写名称、地址、端口、用户名和一种认证方式；第一次不要同时启用跳板机、备用地址和内置 Tailscale。
4. 如果服务器可直达，地址类型选 **手动 / LAN / 公网**；如果必须经过同一 Tailnet，先选系统 Tailscale；只有不想安装系统客户端时才选内置 Tailscale。
5. 保存后点击工作站，再点击 **连接**。首次出现 SSH 指纹时，只在你确认指纹来自目标主机后选择保存。
6. 看到终端提示符、文件页能打开固定目录，并能执行 `pwd`，才算第一阶段成功。
7. 再逐项验证复制、粘贴图片/PDF、Herdr/tmux、断开重连和 Web Preview；任何一项失败，都按本指南第 9 节排查。

> 最小成功标准：能连接 ≠ 已完成配置。必须同时验证“终端可输入、文件目录可读写、凭据未泄露、重连行为符合预期”。

## 1. 开始前需要准备什么

你需要：

- 一台 Windows 10/11 x64 电脑；
- 远程 Linux 电脑上的一个可登录账户；
- Linux 已启用 SSH；
- 至少一条能够到达远程电脑的网络路径；
- 一种服务器支持的 SSH 认证方式。

Herdr 和 tmux 不是建立 SSH 连接的必需品。如果希望 Windows 重启、网络切换或退出 KodeWork 后远程任务仍继续，请在远程 Linux 上安装 Herdr 或 tmux。

### 先判断应该选哪种连接方式

| 你的情况 | KodeWork 中选择 | 需要提前满足 |
| --- | --- | --- |
| Linux 有可访问的 IP 或域名 | LAN、公网或手动地址 | Windows 能访问该主机和 SSH 端口 |
| Windows 和 Linux 已加入同一个 Tailnet | 系统服务 | Windows 已安装并登录 Tailscale |
| 不想单独管理 Windows Tailscale 客户端 | 内置用户态 | 首次注册时有最小权限的 Tailscale Auth Key |
| 只有公网 VPS/堡垒机能访问最终 Linux | 跳板机 | Windows 能 SSH 到跳板机，跳板机能访问最终主机 |

先只配置最简单、最确定的一条路径。第一条连接成功后，再增加备用地址和自动回退。

### 再判断应该选哪种认证方式

| 服务器情况 | 认证方式 | 你需要提供 |
| --- | --- | --- |
| 允许密码登录 | 密码 | 连接时输入 Linux 账户密码 |
| 手里有 OpenSSH 私钥文件 | 自定义私钥 | 本机私钥路径；加密私钥还需要口令 |
| 密钥已加载到 Windows OpenSSH Agent/Pageant | SSH Agent | KodeWork 不接收私钥本体 |
| 服务器会询问 OTP/MFA 或其他问题 | Keyboard-interactive | 按连接窗口显示的问题回答 |

## 2. 安装、升级和选择语言

1. 打开 GitHub 最新 Release。
2. 在附件中下载 Windows x64 MSI。
3. Release 提供 SHA-256 时，将下载文件的校验值与之比较。
4. 运行 MSI。项目取得 Authenticode 证书前，社区构建可能显示“未知发布者”。
5. 第一次启动 KodeWork 时选择 **简体中文** 或 **English**。
6. 以后可以打开 **设置 / Settings** 修改语言。

语言选择是 KodeWork 首次启动页面；当前 MSI 安装向导本身还没有中英文选择页面。

用同一应用标识的新 MSI 安装时，会覆盖升级旧版本并保留本地应用数据。除非 Release 明确要求，否则不需要先卸载。

## 3. 准备远程 Linux

先在可信终端里证明普通 SSH 能登录：

```bash
ssh your-user@your-host
```

如果这里失败，应先修复服务器、网络、防火墙、用户名、端口或认证；此时不要先排查 KodeWork。

可选的持久运行时：

```bash
command -v tmux && tmux -V
command -v herdr && herdr --version
```

KodeWork 会通过命令查找和常见登录 Shell 路径检测 Herdr。如果 Herdr 只安装在私有目录，请保证非交互/登录 SSH Shell 的 `PATH` 也包含该目录。只在某个手动打开的交互 Shell 中可用，并不代表桌面 SSH 客户端也能检测到。

再确定一个可写项目目录，例如 `/home/alice/project`。KodeWork 的文件页以及粘贴图片/PDF 默认会使用工作站里设置的固定远程目录。

## 4. 新建或编辑工作站

点击 **工作站** 旁边的 **+**。以后需要修改时，选中该工作站并点击 **编辑**。

### 每个字段怎么填

| 字段 | 填写内容 | 规则与示例 |
| --- | --- | --- |
| 名称 | 只用于自己识别的名称 | 例如 `GPU 服务器` |
| 地址 | 最终 Linux 的域名或 IP | 例如 `server.example.net`、内网 IP 或 MagicDNS 名称 |
| 端口 | SSH 端口 | 通常是 `22`，范围 1-65535 |
| 用户名 | Linux 登录账户 | 例如 `alice`，不是 Windows 用户名 |
| 运行时 | tmux、Herdr 或普通 Shell | 只有远程登录环境能找到对应程序时才选择 Herdr/tmux |
| 地址类型 | Tailscale、LAN、公网、跳板机或手动 | 只描述网络路径，不代替 SSH 认证 |
| 固定文件目录 | 文件页和粘贴资源的默认目录 | 必须是以 `/` 开头的 Linux 绝对路径 |
| 认证方式 | 密码、自定义私钥、SSH Agent 或 Keyboard-interactive | 必须与服务器策略一致 |
| 私钥文件 | 本机 OpenSSH 私钥路径 | 不要选择以 `.pub` 结尾的公钥文件 |
| 私钥口令 | 解锁加密私钥 | 已保存时留空表示保持不变 |
| 跳板机 | 堡垒机域名、端口、用户名 | 最终主机不能直达时才启用 |
| Tailscale 运行模式 | 系统服务或内置用户态 | Tailscale 只提供网络路径，Linux 登录仍由 SSH 认证 |
| 设备名 | 可选的内置 Tailscale 设备名称 | 使用易识别但不含秘密的名称 |
| 私有状态文件 | 可选的内置 Tailscale 状态路径 | 不需要自己管理时保持为空 |
| Auth Key | Tailscale 首次注册凭据 | 只在内置注册时需要，绝不能提交或公开 |

保存前重点核对地址、用户名、端口和固定文件目录。固定目录填错通常不会阻止 SSH，但文件页和图片/PDF 粘贴会失败。

### 直连地址

选择 LAN、公网或手动，填写最终 Linux 的域名/IP 和 SSH 端口。只有明确了解公网 SSH 风险并已做好加固时才使用公网地址。

### 系统 Tailscale

Windows 已经安装并登录 Tailscale 时，选择 **系统服务**。KodeWork 只读取节点信息，不会修改系统 Tailscale 登录。连接前先在 Tailscale 客户端确认目标 Linux 节点在线可见。

### 内置 Tailscale

希望 KodeWork 独立运行自己的 Tailscale 实例时，选择 **内置用户态**。

1. 在 Tailscale 管理后台创建权限和有效期都尽可能小的 Auth Key。
2. 只把它粘贴到 KodeWork 遮罩显示的 Auth Key 输入框。
3. 保存工作站；密钥会通过系统安全边界保存，不会再次明文显示。
4. 点击连接，等待 Tailscale 注册和 SSH 建连完成。内置进程应隐藏运行；反复闪出命令行窗口属于缺陷。
5. 如果 Auth Key 曾经出现在源码、聊天、截图、Issue 或日志中，立即撤销并重新生成。

### 跳板机

启用跳板机，填写堡垒机域名、端口和用户名；主地址仍然填写最终 Linux。跳板机必须能解析并访问最终地址。先分别测试 Windows 到跳板机、跳板机到目标主机，再测试完整链路。

## 5. 第一次连接

1. 选中工作站。
2. 点击 **连接 / Connect**。
3. 第一次连接会显示 SSH 主机密钥算法和 SHA-256 指纹。
4. 用服务器管理员或另一条可信渠道提供的指纹进行比较。
5. 完全一致后才“信任并保存”。
6. 按提示输入密码、私钥口令或交互式问题答案。
7. 等状态变成 **已连接 / Connected**，并看到 Shell 提示符。

以后如果主机密钥变化，KodeWork 会硬失败阻止连接。在独立确认服务器更换或密钥轮换前，不要绕过警告。

所有地址都超时时，按这个顺序排查：域名解析、TCP/SSH 端口、Tailscale 节点状态、本机/服务器防火墙、用户名与认证、跳板机可达性。

## 6. 怎样才算真正配置成功

不能只看“已连接”三个字。所有适用项都应通过：

- 左侧选中的工作站显示已连接；
- **新建终端** 能打开独立 Shell 并显示提示符；
- 输入 `pwd` 并回车，输出正常且按键没有明显延迟；
- 文件页自动进入设置的固定远程目录；
- 在终端选择文字后，能在 Windows 记事本粘贴出完全相同的内容；
- 点击 **粘贴图片/PDF**，剪贴板中的图片或 PDF 能上传到可写远程目录，远程路径会插入当前终端；
- 远程登录环境确实安装 Herdr/tmux 时，运行时能够被检测并使用；
- 只有建立正确的 SSH 本地转发后，Web Preview 才能打开对应远程端口；
- 断开后重新连接，能够重新获得可用终端；
- 日志和截图中没有密码、私钥、Auth Key、真实基础设施地址或私人文件内容。

不适用的项目要明确标记“不适用”，不要悄悄跳过。

## 7. 日常使用

- **新建终端**：打开一个新的远程 PTY。并发数量有限制，用来保护流畅度和内存。
- **向右分屏 / 向下分屏**：改变布局；每个窗格都有独立关闭按钮。
- **选择文字复制**：选择终端文字后写入 Windows 剪贴板。排查时用记事本做最小验证。
- **粘贴图片/PDF**：只有主动点击后才读取剪贴板，通过 SFTP 流式上传，并把远程路径插入当前终端。目标目录必须存在且可写。
- **语音**：主动触发后采集并把识别文字插入当前终端。
- **文件**：通过 SFTP 浏览和传输；要固定打开位置，请编辑工作站的“固定文件目录”。
- **预览**：把远程开发端口转发到本机回环地址。远程应用必须监听对应端口，其自身 CSP 仍可能限制嵌入。
- **活动**：查看 Action/Run 状态和错误。
- **本机**：通过 Windows ConPTY 打开 PowerShell、CMD 或已安装的 WSL 发行版；它们不连接远程主机。
- **专注**：最大化终端工作区域；退出专注后恢复完整导航。

## 8. 让远程任务持续运行

需要跨 Windows 睡眠、断网、软件退出继续运行的任务，应放在远程 Herdr 或 tmux 内。托盘、自启和自动重连不等于 Windows 本地进程永不退出。

通用 tmux 回退方式：

```bash
tmux new -As kodework
```

以后重新连接并附着同一运行时/会话。如果 KodeWork 提示找不到 Herdr，但你确认已经安装，请用相同 SSH 账户执行 `command -v herdr`，并检查它所在目录是否在非交互登录环境的 PATH 中。

## 9. 常见问题

### 连接超时

- 核对域名/IP 和端口。
- 用可信 SSH 客户端测试同一路径。
- Tailscale 场景确认两端在线且 ACL 允许。
- 跳板机场景分别证明两段链路都能通。

### 内置 Tailscale 无法启动

- 确认完整安装包包含两个内置 Tailscale 组件。
- 重新打开工作站，确认选择“内置用户态”。
- 只有确实需要重新注册时才输入新的、未过期 Auth Key。
- 如果命令窗口反复闪烁，不要无限重试；停止操作并收集已脱敏的诊断信息。

### 检测不到 Herdr

- 用相同 SSH 账户运行 `command -v herdr` 和 `herdr --version`。
- 检查登录/非交互 PATH。
- 环境修好前先使用 tmux 或普通 Shell。

### 显示已复制，但 Windows 剪贴板没有内容

- 点击终端并选择一行短纯文本，然后粘贴到记事本。
- 检查 Windows 剪贴板策略或第三方剪贴板管理器。
- 重连一次，排除失效的终端订阅。
- 报告版本和脱敏后的复现步骤，不要包含终端秘密。

### 看不到或无法使用“粘贴图片/PDF”

- 先选中一个活动远程终端。
- 在 Windows 中复制真实图片或 PDF 文件。
- 确认固定远程目录存在且可写。
- 打开文件页验证 SFTP 能工作。

### 终端最下面一行被裁掉

- 退出再进入专注模式，然后调整一次窗口大小。
- 记录 Windows 显示缩放比例和软件版本。
- 能稳定复现时，提交已遮挡服务器信息的截图、缩放比例和窗口尺寸。

### 文件传输慢

- 用相同网络路径在其他可信工具中比较速度。
- 避免不必要的跳板机或公网回退路径。
- 检查延迟、丢包、服务器磁盘速度和 CPU。
- 本地传输连续性需要软件保持运行；远程命令只有放入 Herdr/tmux 才能跨客户端退出继续。

## 10. 安全诊断和恢复方法

分享诊断信息前，删掉密码、Auth Key、私钥路径、真实主机名/IP、用户名、终端内容和私人文件名。优先提供简短操作步骤和界面显示的错误文字。

如果配置已经改乱：

1. 编辑工作站，只保留一条确定可用的地址，其余备用路径全部禁用。
2. 把运行时改成普通 Shell。
3. 只使用一种已知可用的密码或密钥认证。
4. 连接并完成“真正配置成功”检查表。
5. 再把 Tailscale、跳板机、Herdr/tmux 和备用地址逐项加回，每加一项就验证一次。

这样可以定位到底是网络、SSH、认证、运行时还是文件传输层出错，避免一次修改多个变量。
